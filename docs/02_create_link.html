Redissolving candidate centerlines and splitting only at snapped model nodes to produce true-shape link pieces

CandidateTDMRoadLinks is fully re-dissolved into maximal topological chains per VERT_LEVEL (undoing incidental arcpy junction cuts), then split only at snapped WFRC model-node and CC-attachment positions to produce the raw building-block pieces for true-shape link conflation. Lineage/display attributes (OBJECTID, UNIQUE_ID, DOT_FCLASS, etc.) are reattached onto each piece via a midpoint-nearest join against CandidateTDMRoadLinks.

3 Part A — Full Network Redissolve

CandidateTDMRoadLinks is already pre-cut at arcpy-style junction points (see 00_data_preparation.qmd’s rcl_merge), including boundaries between freeway/ramp/CD rows and surface-street rows wherever they merely touch — not just at genuine multi-way branches. To make the final true-shape split points come only from snapped model nodes, every row is re-dissolved into maximal topological chains first, per VERT_LEVEL (freeway and surface rows combined within a level — genuine branch points, where 3+ lines share an endpoint, still remain hard boundaries after dissolve; only incidental class-boundary splits are undone).

VERT_LEVEL isolation is preserved deliberately: dissolving across levels would incorrectly fuse an elevated/tunnel structure with an at-grade road sharing the same XY footprint (see dissolve_and_singlepart docstring).

Show the code

4 Part B — Resolve Snap Coordinates

nodes_snapped.gpkg stores snapped_x_round / snapped_y_round rounded to 2 decimal places (cm precision). Splitting and M-value operations require coordinates that exactly match a vertex stored in the centerline geometry. For each snapped node, this step finds the nearest unique centerline vertex within 5 cm and records its full-precision coordinate.

FixedTransit_Rail nodes are excluded — they snap to GTFS rail infrastructure (CRT stations, LRT midpoints), not to road centerlines, so they are never road centerline split points.

5 Part C — Split at Snapped Nodes

gdf_fulldissolve (Part A) — not the original CandidateTDMRoadLinks rows — is split at every model-node snap point, every CC attachment snap point, and every external station snap point, so piece boundaries come only from snapping, never from incidental arcpy junction cuts. Points that project to within 0.1 mm of a component’s existing endpoint are skipped (already a boundary). After all splits, each resulting piece is bounded exclusively by: - a snapped model node position, - a snapped CC attachment node position, - a snapped external station node position, or - a genuine branch point already present in gdf_fulldissolve.

No lineage keys are carried through this split (id_cols=()) — a redissolved row no longer maps 1:1 to a single original OBJECTID. Lineage/display attributes are reattached afterward via midpoint join (Part D).

A CC or external-station node can share its N with a node that the main greedy snapper already resolved to a real road-junction position (e.g. a zone centroid loaded at an actual intersection). 03_transfer_attributes.qmd already gives the road-snapped position precedence for that N and discards the CC/EXT coordinate — but snap_cc_nodes() computes the CC/EXT position independently (nearest-line projection from the node’s own raw coordinate), so it rarely lands exactly on the road-snapped point. Left unfiltered, this produces a redundant split a few metres from the real node: a sliver piece whose far end is an orphaned coordinate coord_to_node will never resolve, showing up downstream as spurious a_only/b_only. Nodes already road- snapped are excluded here so their N contributes exactly one split point (the road one), not two.

6 Part D — Build Pieces Layer, Reattach Lineage, and Export

Extract start/end endpoint coordinates for each piece (rounded to 2 dp for matching against snapped_x_round / snapped_y_round in the next stage). Since splitting now runs against the redissolved gdf_fulldissolve layer, a piece no longer maps 1:1 to a single original CandidateTDMRoadLinks OBJECTID — lineage/display attributes (TRANSFER_COLS) are reattached via the same midpoint-nearest-join approach 00_data_preparation.qmd uses to transfer attributes from raw centerlines onto CandidateTDMRoadLinks in the first place, this time from CandidateTDMRoadLinks onto each piece.

Show the code 
pieces = gdf_pieces_split.geometry.tolist()
start_coords = np.array([p.coords[0] for p in pieces])
end_coords   = np.array([p.coords[-1] for p in pieces])

gdf_pieces = gpd.GeoDataFrame(
    {
        "piece_id": np.arange(len(pieces)),
        "x_start":  np.round(start_coords[:, 0], 2),
        "y_start":  np.round(start_coords[:, 1], 2),
        "x_end":    np.round(end_coords[:, 0], 2),
        "y_end":    np.round(end_coords[:, 1], 2),
        "length_m": np.array([p.length for p in pieces]),
        "geometry": pieces,
    },
    crs=CRS_UTM,
)

CandidateTDMRoadLinks contains a small number of standalone sub-centimetre “stub” features (max ~6 mm, confirmed by direct OBJECTID lookup) — digitizing artifacts, not anything this pipeline creates. Because split_candidate_links never cuts a component shorter than its 0.5 m _EPS, each stub passes through whole as its own piece; since both of its (near-identical) endpoints round to the same snapped-node coordinate, Stage 3 later resolves A_piece == B_piece for it — a spurious self-loop. Genuine physical loop roads (cloverleaf/collector loops that legitimately start and end at the same point) are tens of metres to several kilometres long, so a length_m < 1 m gate removes only the artifacts.

Show the code 
n_before_drop = len(gdf_pieces)

## Part C — Split at Snapped Nodes

`gdf_fulldissolve` (Part A) — not the original `CandidateTDMRoadLinks` rows —
is split at every model-node snap point, every CC attachment snap point, and
every external station snap point, so piece boundaries come only from
snapping, never from incidental arcpy junction cuts. Points that project to
within 0.1 mm of a component's existing endpoint are skipped (already a
boundary). After all splits, each resulting piece is bounded exclusively by:
- a snapped model node position,
- a snapped CC attachment node position,
- a snapped external station node position, or
- a genuine branch point already present in `gdf_fulldissolve`.

No lineage keys are carried through this split (`id_cols=()`) — a redissolved
row no longer maps 1:1 to a single original `OBJECTID`. Lineage/display
attributes are reattached afterward via midpoint join (Part D).

A CC or external-station node can share its `N` with a node that the main
greedy snapper already resolved to a real road-junction position (e.g. a
zone centroid loaded at an actual intersection). `03_transfer_attributes.qmd`
already gives the road-snapped position precedence for that `N` and discards
the CC/EXT coordinate — but `snap_cc_nodes()` computes the CC/EXT position
independently (nearest-line projection from the node's own raw coordinate),
so it rarely lands exactly on the road-snapped point. Left unfiltered, this
produces a redundant split a few metres from the real node: a sliver piece
whose far end is an orphaned coordinate `coord_to_node` will never resolve,
showing up downstream as spurious `a_only`/`b_only`. Nodes already road-
snapped are excluded here so their `N` contributes exactly one split point
(the road one), not two.

```{python}
road_snapped_ids = set(gdf_nodes_road.loc[gdf_nodes_road["snapped"].fillna(False), "N"].astype(int))

cc_resolved = gdf_cc_snapped[
    gdf_cc_snapped["snap_resolved"] & ~gdf_cc_snapped["N"].astype(int).isin(road_snapped_ids)
]
cc_snap_points = [
    Point(row["x_snap"], row["y_snap"])
    for _, row in cc_resolved.iterrows()
]
ext_resolved = gdf_ext_snapped[
    gdf_ext_snapped["snap_resolved"] & ~gdf_ext_snapped["N"].astype(int).isin(road_snapped_ids)
]
ext_snap_points = [
    Point(row["x_snap"], row["y_snap"])
    for _, row in ext_resolved.iterrows()
]
all_snap_points = snap_points_exact + cc_snap_points + ext_snap_points
n_cc_dual = int((gdf_cc_snapped["snap_resolved"] & gdf_cc_snapped["N"].astype(int).isin(road_snapped_ids)).sum())
n_ext_dual = int((gdf_ext_snapped["snap_resolved"] & gdf_ext_snapped["N"].astype(int).isin(road_snapped_ids)).sum())
n_cc_unresolved = len(gdf_cc_snapped) - gdf_cc_snapped["snap_resolved"].sum()
n_ext_unresolved = len(gdf_ext_snapped) - gdf_ext_snapped["snap_resolved"].sum()
print(
    f"Split points: {len(snap_points_exact):,} (model nodes) + "
    f"{len(cc_snap_points):,} (CC attachment, {n_cc_unresolved:,} unresolved + "
    f"{n_cc_dual:,} dual-identity with a road node excluded) + "
    f"{len(ext_snap_points):,} (external station, {n_ext_unresolved:,} unresolved + "
    f"{n_ext_dual:,} dual-identity with a road node excluded) "
    f"= {len(all_snap_points):,} total"
)
```

```{python}
print(f"Splitting {len(gdf_fulldissolve):,} redissolved chains at {len(all_snap_points):,} points …")
gdf_pieces_split = split_candidate_links(gdf_fulldissolve, all_snap_points, id_cols=())
print(f"Pieces after split: {len(gdf_pieces_split):,}")
```

## Part D — Build Pieces Layer, Reattach Lineage, and Export

Extract start/end endpoint coordinates for each piece (rounded to 2 dp for
matching against `snapped_x_round / snapped_y_round` in the next stage). Since
splitting now runs against the redissolved `gdf_fulldissolve` layer, a piece
no longer maps 1:1 to a single original `CandidateTDMRoadLinks` `OBJECTID` —
lineage/display attributes (`TRANSFER_COLS`) are reattached via the same
midpoint-nearest-join approach `00_data_preparation.qmd` uses to transfer
attributes from raw centerlines onto `CandidateTDMRoadLinks` in the first
place, this time from `CandidateTDMRoadLinks` onto each piece.

```{python}
pieces = gdf_pieces_split.geometry.tolist()
start_coords = np.array([p.coords[0] for p in pieces])
end_coords   = np.array([p.coords[-1] for p in pieces])

gdf_pieces = gpd.GeoDataFrame(
    {
        "piece_id": np.arange(len(pieces)),
        "x_start":  np.round(start_coords[:, 0], 2),
        "y_start":  np.round(start_coords[:, 1], 2),
        "x_end":    np.round(end_coords[:, 0], 2),
        "y_end":    np.round(end_coords[:, 1], 2),
        "length_m": np.array([p.length for p in pieces]),
        "geometry": pieces,
    },
    crs=CRS_UTM,
)
```

`CandidateTDMRoadLinks` contains a small number of standalone sub-centimetre
"stub" features (max ~6 mm, confirmed by direct `OBJECTID` lookup) — digitizing
artifacts, not anything this pipeline creates. Because `split_candidate_links`
never cuts a component shorter than its 0.5 m `_EPS`, each stub passes through
whole as its own piece; since both of its (near-identical) endpoints round to
the same snapped-node coordinate, Stage 3 later resolves `A_piece == B_piece`
for it — a spurious self-loop. Genuine physical loop roads (cloverleaf/collector
loops that legitimately start and end at the same point) are tens of metres to
several kilometres long, so a `length_m < 1 m` gate removes only the artifacts.

```{python}
n_before_drop = len(gdf_pieces)
degenerate_mask = (
    (gdf_pieces["x_start"] == gdf_pieces["x_end"])
    & (gdf_pieces["y_start"] == gdf_pieces["y_end"])
    & (gdf_pieces["length_m"] < 1.0)
)
n_degenerate = int(degenerate_mask.sum())
gdf_pieces = gdf_pieces[~degenerate_mask].reset_index(drop=True)
print(
    f"Dropped {n_degenerate:,} / {n_before_drop:,} degenerate zero-length pieces "
    f"(start == end, length < 1 m) — pre-existing near-duplicate-vertex stub "
    f"features already present as standalone rows in CandidateTDMRoadLinks, "
    f"not created by this pipeline. Real closed-loop roads (cloverleaf/collector "
    f"loops, tens of metres to several km long) are left untouched — the length "
    f"gate cleanly separates the two populations with a >3,000x margin."
)

gdf_pieces = transfer_attributes_by_midpoint(gdf_pieces, gdf_centerlines, TRANSFER_COLS)

n_null = gdf_pieces[TRANSFER_COLS].isna().any(axis=1).sum()
print(f"Pieces with a null transferred attribute: {n_null:,} / {len(gdf_pieces):,}")

PATHS["out_link_pieces"].parent.mkdir(parents=True, exist_ok=True)
gdf_pieces.to_file(PATHS["out_link_pieces"], driver="GPKG")
print(f"Exported {len(gdf_pieces):,} pieces → {PATHS['out_link_pieces']}")
```
