3 Part A — Origin Processing (Network Nodes)

A1 — Functional Type Flags

nodes_on(gdf_nodes, gdf_links, ft_codes) returns True for any node whose N appears as endpoint A or B of at least one link whose FT code is in ft_codes.

Flags are non-exclusive — a node touching both a freeway and a ramp link will be True for both Freeway and Ramp. Mutual exclusion is enforced later in the topology cascade (§A3).

A2 — Link Count, Neighbor Count, and Direction

count_links adds LinkCount — raw endpoint references per node, used for the distribution chart and diagnostics.

count_neighbors adds NeighborCount — the number of distinct neighboring nodes. This is the topologically correct pseudonode test: LinkCount breaks on bidirectional roads stored as two directional records (a pseudonode appears 4 times → LinkCount=4, not 2), while NeighborCount is always 2 for a true shape vertex regardless of storage convention.

A node is an is_pseudo shape vertex if and only if all three conditions hold: 1. NeighborCount == 2 — lies on a single path between two real junctions. 2. LinkFTCount == 1 — all connected links share the same exact FT code. A node where FT changes (e.g. FT 32→33) has a real physical endpoint in the centerline data and must be sent to snapping. 3. LinkLNCount == 1 — all connected links carry the same lane count. A lane-drop or lane-add node must not be dissolved away, as doing so would erase a model attribute boundary that affects TDM impedance.

assign_node_directions produces two direction columns (see docstring): - link_directions — freeway-priority cascade; used in passes (a) and (c). - fw_directions — freeway links only, majority-vote; used in pass (b) gore nodes.

Show the code 
gdf_nodes = count_links(gdf_nodes, gdf_links)
gdf_nodes = count_neighbors(gdf_nodes, gdf_links)
gdf_nodes = assign_node_directions(gdf_nodes, gdf_links, freeway_ft_codes=FW_CODES)

# Assign one class label per link using the already-defined mutually exclusive masks.
_link_class = pd.Series("other", index=gdf_links.index)
_link_class[FWY_LINK_MASK]  = "freeway"
_link_class[RAMP_LINK_MASK] = "ramp"
_link_class[SURFACE_LINK_MASK] = "surface"
_link_class[gdf_links[FT_COL].isin({70, 80})] = "transit"

# For each node, count how many distinct link classes touch it.
_stacked_class = pd.concat([
    gdf_links[["A"]].assign(cls=_link_class.values).rename(columns={"A": "N"}),
    gdf_links[["B"]].assign(cls=_link_class.values).rename(columns={"B": "N"}),
], ignore_index=True)
_class_counts = _stacked_class.groupby("N")["cls"].nunique()
gdf_nodes["LinkClassCount"] = gdf_nodes["N"].map(_class_counts).fillna(0).astype(int)

# Count distinct FT codes per node.
# Stricter than LinkClassCount: nodes where FT changes (e.g. FT=32→33) register
# LinkFTCount=2 even though both belong to the freeway class.  Used in the
# link true-shape dissolution step to preserve model link boundaries where posted
# speed or facility sub-type changes — dissolving those nodes would corrupt TDM impedance.
_stacked_ft = pd.concat([
    gdf_links[["A", FT_COL]].rename(columns={"A": "N"}),
    gdf_links[["B", FT_COL]].rename(columns={"B": "N"}),
], ignore_index=True)
_ft_counts = _stacked_ft.groupby("N")[FT_COL].nunique()
gdf_nodes["LinkFTCount"] = gdf_nodes["N"].map(_ft_counts).fillna(0).astype(int)

# Count distinct lane counts per node — lane-drop/lane-add nodes must be snapped
# even when FT is uniform, because dissolving them would erase the lane change.
_stacked_ln = pd.concat([
    gdf_links[["A", "LN_2027"]].rename(columns={"A": "N"}),
    gdf_links[["B", "LN_2027"]].rename(columns={"B": "N"}),
], ignore_index=True)
_ln_counts = _stacked_ln.groupby("N")["LN_2027"].nunique()
gdf_nodes["LinkLNCount"] = gdf_nodes["N"].map(_ln_counts).fillna(0).astype(int)

# Pseudonode: shape vertex on a single homogeneous path — no physical snap target.
# Requires uniform FT AND uniform lane count: a lane-drop node has a real physical
# endpoint in the centerline data and must not be dissolved away. is_pseudo gates
# Part A3's node_type assignment below (a pseudonode gets no node_type / is never
# sent to spatial snapping) and must stay this strict — a snapping target still
# needs FT/LN uniformity to be a safe physical match.
gdf_nodes["is_pseudo"] = (
    (gdf_nodes["NeighborCount"] == 2)
    & (gdf_nodes["LinkFTCount"] == 1)
    & (gdf_nodes["LinkLNCount"] == 1)
)

# Broader topological pass-through flag, for Stage 3 chain dissolution only
# (03_transfer_attributes.qmd) — NOT used for snapping eligibility here.
# NeighborCount==2 alone is a sufficient safety guarantee on its own: a node
# with exactly two distinct neighbors has exactly one way to walk through it,
# regardless of whether FT, lane count, or link class (freeway/ramp/surface
# designation) changes there. Dropping the uniform-FT/uniform-LN/uniform-class
# requirements here (unlike is_pseudo above) lets Stage 3 dissolve through
# real FT/lane-transition and class-transition nodes that have no physical
# vertex of their own — the dominant cause of `endpoints_only` pieces, see
# _plan/freeway-endpoint-pool-diagnosis.md and the node-30208 (Antelope Island
# Causeway) example that first surfaced it. A node with 3+ neighbors is never
# included regardless — with a real branch, topology alone can't tell you
# which branch continues the same physical road (see dissolve_pseudonodes'
# docstring), so it must stay a hard boundary.
gdf_nodes["is_topo_passthrough"] = gdf_nodes["NeighborCount"] == 2

A3 — Node Topology Classification

Eight mutually-exclusive node_type labels. Transit is evaluated first and takes priority over all road-class combinations. The remaining seven labels derive from the full combinatorics of the (Freeway, Ramp, Surface) flags.

HOV/managed-lane nodes (FT 37-39) were filtered at load time, so they contribute no flags; those nodes fall to “surface” and are not snapped. Pseudonodes (LinkCount == 2) are shape vertices with no physical counterpart.

Show the code

is_ramp_node    = gdf_nodes["Ramp"]         & no_pseudo
is_surface_node = gdf_nodes["Surface"]      & no_pseudo

# Full combinatorics of the three link classes → 7 node types.
# Transit is evaluated first — station nodes get "transit" regardless of any
# road-class links they may also touch.
# Most-specific road combinations (all three flags) are evaluated next.
gdf_nodes["node_type"] = np.select(
    [
        is_transit_node,                                  # fixed rail station
        is_fwy_node &  is_ramp_node &  is_surface_node,  # fwy+ramp+sf → at-grade interchange

B2 — Classify Segments

Three mutually exclusive boolean flags per segment. Primary authority is DOT_FCLASS for freeway identification; DOT_RTNAME (UDOT LRS) supplements with explicit route numbers and ramp/CD facility characters. ONEWAY in (1, 2) elevates divided Principal Arterials into the freeway class (domain CVDomain_OneWay: 0=Two-way, 1=One-way direction of arc, 2=One-way opposite direction of arc).

DOT_RTNAME layout (11 characters, zero-padded):

### A1 — Functional Type Flags

`nodes_on(gdf_nodes, gdf_links, ft_codes)` returns True for any node whose
N appears as endpoint A or B of at least one link whose FT code is in `ft_codes`.

Flags are **non-exclusive** — a node touching both a freeway and a ramp link
will be True for both `Freeway` and `Ramp`. Mutual exclusion is enforced later
in the topology cascade (§A3).

```{python}
# FT_2027 code reference
# ─────────────────────────────────────────────────────────────────────────
# Class 1 — Freeway Mainline (FW_CODES):
#   12-15  Expressway (limited-access, divided)
#   22-26  MM freeway (posted 55-75 mph, MM series)
#   32-36  Freeway    (posted 55-75 mph, Fwy series)
#   40     Express / managed-access freeway
#   FT=2 AND DIRECTION=1: directional Principal Arterial links representing
#         physically separated roadways (e.g. divided expressways coded as PA).
#

#   20/30  Loop ramps  |  28/29  MM on/off ramps  |  41/42  Fwy on/off ramps

#   2/3  Principal/Minor Arterial  |  4/5  Major/Minor Collector  |  6/7  Local/Unpaved
```

### A2 — Link Count, Neighbor Count, and Direction

`count_links` adds `LinkCount` — raw endpoint references per node, used for the
distribution chart and diagnostics.

`count_neighbors` adds `NeighborCount` — the number of **distinct** neighboring
nodes. This is the topologically correct pseudonode test: `LinkCount` breaks on
bidirectional roads stored as two directional records (a pseudonode appears 4
times → LinkCount=4, not 2), while NeighborCount is always 2 for a true shape
vertex regardless of storage convention.

A node is an `is_pseudo` shape vertex if and only if all three conditions hold:
1. **NeighborCount == 2** — lies on a single path between two real junctions.
2. **LinkFTCount == 1** — all connected links share the same exact FT code.
   A node where FT changes (e.g. FT 32→33) has a real physical endpoint in the
   centerline data and must be sent to snapping.
3. **LinkLNCount == 1** — all connected links carry the same lane count.
   A lane-drop or lane-add node must not be dissolved away, as doing so would
   erase a model attribute boundary that affects TDM impedance.

`assign_node_directions` produces two direction columns (see docstring):
- `link_directions` — freeway-priority cascade; used in passes (a) and (c).
- `fw_directions`   — freeway links only, majority-vote; used in pass (b) gore nodes.

```{python}
gdf_nodes = count_links(gdf_nodes, gdf_links)
gdf_nodes = count_neighbors(gdf_nodes, gdf_links)

_link_class = pd.Series("other", index=gdf_links.index)
_link_class[FWY_LINK_MASK]  = "freeway"
_link_class[RAMP_LINK_MASK] = "ramp"
_link_class[SURFACE_LINK_MASK] = "surface"
_link_class[gdf_links[FT_COL].isin({70, 80})] = "transit"

# For each node, count how many distinct link classes touch it.
_stacked_class = pd.concat([
    gdf_links[["A"]].assign(cls=_link_class.values).rename(columns={"A": "N"}),
    gdf_links[["B"]].assign(cls=_link_class.values).rename(columns={"B": "N"}),
], ignore_index=True)
_class_counts = _stacked_class.groupby("N")["cls"].nunique()
gdf_nodes["LinkClassCount"] = gdf_nodes["N"].map(_class_counts).fillna(0).astype(int)

# Count distinct FT codes per node.
# Stricter than LinkClassCount: nodes where FT changes (e.g. FT=32→33) register
# LinkFTCount=2 even though both belong to the freeway class.  Used in the
# link true-shape dissolution step to preserve model link boundaries where posted
# speed or facility sub-type changes — dissolving those nodes would corrupt TDM impedance.
_stacked_ft = pd.concat([
    gdf_links[["A", FT_COL]].rename(columns={"A": "N"}),
    gdf_links[["B", FT_COL]].rename(columns={"B": "N"}),
], ignore_index=True)
_ft_counts = _stacked_ft.groupby("N")[FT_COL].nunique()
gdf_nodes["LinkFTCount"] = gdf_nodes["N"].map(_ft_counts).fillna(0).astype(int)

# Count distinct lane counts per node — lane-drop/lane-add nodes must be snapped
# even when FT is uniform, because dissolving them would erase the lane change.
_stacked_ln = pd.concat([
    gdf_links[["A", "LN_2027"]].rename(columns={"A": "N"}),
    gdf_links[["B", "LN_2027"]].rename(columns={"B": "N"}),
], ignore_index=True)
_ln_counts = _stacked_ln.groupby("N")["LN_2027"].nunique()
gdf_nodes["LinkLNCount"] = gdf_nodes["N"].map(_ln_counts).fillna(0).astype(int)

# Pseudonode: shape vertex on a single homogeneous path — no physical snap target.
# Requires uniform FT AND uniform lane count: a lane-drop node has a real physical
# endpoint in the centerline data and must not be dissolved away. is_pseudo gates
# Part A3's node_type assignment below (a pseudonode gets no node_type / is never
# sent to spatial snapping) and must stay this strict — a snapping target still
# needs FT/LN uniformity to be a safe physical match.
gdf_nodes["is_pseudo"] = (
    (gdf_nodes["NeighborCount"] == 2)
    & (gdf_nodes["LinkFTCount"] == 1)
    & (gdf_nodes["LinkLNCount"] == 1)
)

# Broader topological pass-through flag, for Stage 3 chain dissolution only
# (03_transfer_attributes.qmd) — NOT used for snapping eligibility here.
# NeighborCount==2 alone is a sufficient safety guarantee on its own: a node
# with exactly two distinct neighbors has exactly one way to walk through it,
# regardless of whether FT, lane count, or link class (freeway/ramp/surface
# designation) changes there. Dropping the uniform-FT/uniform-LN/uniform-class
# requirements here (unlike is_pseudo above) lets Stage 3 dissolve through
# real FT/lane-transition and class-transition nodes that have no physical
# vertex of their own — the dominant cause of `endpoints_only` pieces, see
# _plan/freeway-endpoint-pool-diagnosis.md and the node-30208 (Antelope Island
# Causeway) example that first surfaced it. A node with 3+ neighbors is never
# included regardless — with a real branch, topology alone can't tell you
# which branch continues the same physical road (see dissolve_pseudonodes'
# docstring), so it must stay a hard boundary.
gdf_nodes["is_topo_passthrough"] = gdf_nodes["NeighborCount"] == 2
```

### B2 — Classify Segments

Three mutually exclusive boolean flags per segment. Primary authority is
`DOT_FCLASS` for freeway identification; `DOT_RTNAME` (UDOT LRS) supplements with
explicit route numbers and ramp/CD facility characters. `ONEWAY` in (`1`, `2`)
elevates divided Principal Arterials into the freeway class (domain CVDomain_OneWay:
0=Two-way, 1=One-way direction of arc, 2=One-way opposite direction of arc).

```
DOT_RTNAME layout (11 characters, zero-padded):
  [0:4]  Route number      e.g. "0015" = I-15, "0154" = Bangerter
  [4]    LRS direction     "P" = primary (NB/EB),  "N" = negative (SB/WB)
  [5]    Facility type     " " = mainline, "R" = ramp, "C" = collector-distributor
  [6:]   Sequence/suffix   varies
```

These flags flow into every endpoint pool and type-tier decision, making this
the **primary place to audit** when snapping results look wrong.

```{python}
# ── Controlled-access corridors in the Wasatch Front study area ───────────
# Adding / removing a route here is the primary tuning lever for freeway coverage.
# These are the 4-character UDOT route numbers (DOT_RTNAME[0:4]).
FREEWAY_ROUTES = {
    "0015",   # Interstate 15         (primary N-S spine)
    "0067",   # Legacy Parkway        (limited-access, no ramps)
    "0080",   # Interstate 80         (E-W, SLC to Parley's Canyon)
    "0084",   # Interstate 84         (Ogden corridor)
    "0089",   # US-89                 (surface in places — watch for mis-classification)
    "0092",   # Timpanogos Highway    (SR-92, American Fork Canyon)
    "0154",   # Bangerter Highway     (semi-controlled ring road)
    "0177",   # West Davis Corridor   (new build, limited segments)
    "0201",   # SR-201                (West Valley connector)
    "0215",   # Interstate 215        (belt route, SLC)
}

rtname  = active_cl["DOT_RTNAME"].fillna("")

# ── Shared exclusion flags ────────────────────────────────────────────────
# Ramp/CD character check: DOT_RTNAME LIKE '%R%' or '%C%', excluding DupRoute.
_has_R_or_C = rtname.str.contains("R", na=False) | rtname.str.contains("C", na=False)
_not_duprt  = rtname != "DupRoute"
_not_ramp_cd = ~_has_R_or_C | ~_not_duprt  # True when segment is NOT a ramp/CD

# ── Class 1: Freeway Mainline ─────────────────────────────────────────────
# Primary: DOT_FCLASS identifies interstate / other freeway geometry.
# Secondary: explicit UDOT route number is a controlled-access corridor.
# Tertiary: Principal Arterial with ONEWAY in ('1','2') represents a
#           physically separated directional roadway.
#           ONEWAY domain (CVDomain_OneWay): 0=Two-way, 1=One-way direction
#           of arc, 2=One-way opposite direction of arc.
# All three require exclusion of ramp/CD facility chars and DupRoute aliases.
_is_fclass_fwy = active_cl["DOT_FCLASS"].isin(["Interstate", "Other Freeway"])
_is_named_fwy  = rtname.str.slice(0, 4).isin(FREEWAY_ROUTES)
_is_dir_pa = (
    (active_cl["DOT_FCLASS"] == "Principal Arterial")
    & active_cl["ONEWAY"].isin(["1", "2"])
)

active_cl["is_freeway"] = (
    (_is_fclass_fwy | _is_named_fwy | _is_dir_pa)
    & ~_has_R_or_C
    & _not_duprt
)

# ── Class 2: Ramps and CDs ────────────────────────────────────────────────
# Strictly determined by DOT_RTNAME structure: any R or C facility character,
# excluding the DupRoute administrative alias.
active_cl["is_interchange"] = _has_R_or_C & _not_duprt

# ── Class 3: Surface Streets ──────────────────────────────────────────────
# Everything that is not freeway mainline or ramp/CD.
# Explicitly excludes DOT_FCLASS values that fall outside the three classes
# (already filtered in B1, but guard here for completeness).
active_cl["is_surface"] = (
    ~active_cl["is_freeway"]
    & ~active_cl["is_interchange"]
    & active_cl["DOT_FCLASS"].notna()
    & ~active_cl["DOT_FCLASS"].isin(["Interstate", "Other Freeway", "Instituitional", ""])  # note: source-data typo
)

print("Segment-level classification:")
print(f"  is_freeway     (mainline):   {active_cl['is_freeway'].sum():,}")
print(f"  is_interchange (ramp / CD):  {active_cl['is_interchange'].sum():,}")
print(f"  is_surface     (all others): {active_cl['is_surface'].sum():,}")
print(f"  unclassified   (none):       {(~active_cl['is_freeway'] & ~active_cl['is_interchange'] & ~active_cl['is_surface']).sum():,}")
print(f"  both fwy + ic  (gore segs):  {(active_cl['is_freeway'] & active_cl['is_interchange']).sum():,}")
print(f"  total active:                {len(active_cl):,}")
```

### B4 — Deduplicate by Tolerance-Based Clustering

Cluster raw endpoints by true single-linkage distance (`cluster_endpoints`,
`ENDPOINT_CLUSTER_TOLERANCE_M` = 1cm) rather than a rounded-coordinate grid
bucket — two points 2mm apart that happen to round into different 1cm grid
cells (e.g. `10.004999` → `10.00` vs `10.005001` → `10.01`) are now correctly
merged. Aggregate type flags with OR — a cluster is `is_freeway=True` if any
freeway segment terminates there. The output geometry keeps the exact
(unrounded) coordinate of one contributing raw endpoint rather than
reconstructing a point from the rounded key, so `gdf_ep_unique` — and every
node later snapped onto it — stays bit-exact with a real `CandidateTDMRoadLinks`
vertex instead of sitting on a 1cm quantization grid. `x_round`/`y_round` are
still carried through (first raw point) for QGIS inspection and for
`link_utils.resolve_snap_coords`'s downstream nearest-vertex lookup, which
is out of scope for this change.

```{python}
gdf_ep_raw["cluster_id"] = cluster_endpoints(
    gdf_ep_raw, tolerance_m=ENDPOINT_CLUSTER_TOLERANCE_M
)

print(
    f"Endpoint clusters: {len(cluster_sizes):,} clusters "
    f"from {len(gdf_ep_raw):,} raw points (tolerance={ENDPOINT_CLUSTER_TOLERANCE_M}m)"
)
print(f"Cluster size distribution: {cluster_sizes.value_counts().sort_index().to_dict()}")

# Chaining-risk QA: single-linkage clustering can in principle chain several
# close-but-distinct vertices together. Flag any cluster whose raw points
# span more than 2x tolerance end-to-end (bounding-box diagonal as a cheap
# upper bound on max pairwise distance).
_span = pd.DataFrame(
    {
        "cluster_id": gdf_ep_raw["cluster_id"],
        "x": gdf_ep_raw.geometry.x.values,
        "y": gdf_ep_raw.geometry.y.values,

).groupby("cluster_id").agg(x_span=("x", np.ptp), y_span=("y", np.ptp))
_span["diag_m"] = np.hypot(_span["x_span"], _span["y_span"])
_chaining_risk = _span[_span["diag_m"] > 2 * ENDPOINT_CLUSTER_TOLERANCE_M]
if len(_chaining_risk):
    print(f"WARNING: {len(_chaining_risk)} cluster(s) span > {2 * ENDPOINT_CLUSTER_TOLERANCE_M:.2f}m — possible chaining:")
    print(_chaining_risk.sort_values("diag_m", ascending=False).head(10).to_string())
else:
    print("No chaining risk detected — all clusters within 2x tolerance.")

ep_agg = gdf_ep_raw.groupby("cluster_id", as_index=False).agg(
    x_round=("x_round", "first"),
    y_round=("y_round", "first"),
    is_freeway=("is_freeway", "any"),
    is_interchange=("is_interchange", "any"),
    is_surface=("is_surface", "any"),
    fw_route_count=(
        "dot_rtname",
        lambda s: s[gdf_ep_raw.loc[s.index, "is_freeway"]].str[:4].nunique(),

    geometry=("geometry", "first"),
)
gdf_ep_unique = gpd.GeoDataFrame(ep_agg, geometry="geometry", crs=CRS_UTM)
gdf_ep_unique["ep_uid"] = gdf_ep_unique["cluster_id"]

print(f"Unique endpoints: {len(gdf_ep_unique):,}")
print(
    f"  freeway-only   : {(gdf_ep_unique['is_freeway'] & ~gdf_ep_unique['is_interchange']).sum():,}"
)
print(
    f"  freeway + ramp : {(gdf_ep_unique['is_freeway'] & gdf_ep_unique['is_interchange']).sum():,}"
)
print(
    f"  ramp-only      : {(~gdf_ep_unique['is_freeway'] & gdf_ep_unique['is_interchange'] & ~gdf_ep_unique['is_surface']).sum():,}"
)
print(f"  surface        : {gdf_ep_unique['is_surface'].sum():,}")
```

### D1 — Freeway and Interchange Snapping

Four passes in topology-priority order: (a) pure freeway, (a2) at-grade freeway
crossings, (b) gore/gore_sf, (c) mid-ramp. All include `fwy_sf` in the D1 debug
export so at-grade crossing snaps can be verified before running surface snapping.

```{python}
# ── Endpoint pools ────────────────────────────────────────────────────────
#
# Each pool is now built from node_utils.allowed_ep_types(), which reads
# straight off _TYPE_TIER — the same table _spatial_snap uses to score
# candidates — instead of a hand-typed ep_type list. Diagnosis (2026-07-16)
# found the previous hand-typed pools had silently drifted narrower than
# _TYPE_TIER (and this section's own comments) already declared permitted:
# e.g. ("fwy", "gore"): 1 was documented as a Tier-1 fallback, but "gore"
# endpoints were never actually in the fwy pool below, so that fallback was
# dead code. Freeway/interchange node types took the brunt of it: their
# nearest real physical vertex is disproportionately a Tier-1 type one class
# over (arcpy only cuts centerlines at interchanges, not at the FT/lane
# -transition points that generate many freeway model nodes), and that
# vertex was almost always well within the search radius — median 100-150m
# vs. a 500m threshold — it just never reached the candidate pool. See
# node_utils.allowed_ep_types docstring for the full writeup. Any deviation
# from the raw tier table below is a deliberate, separately-justified
# business rule, called out inline.

# Pass (a) — fwy nodes → {fwy, gore, fwy_sf} (_TYPE_TIER tier ≤ 1 for "fwy").
#   ramp/surface are absent from _TYPE_TIER's "fwy" row entirely (not merely
#   tier>1), so they stay excluded — the divided-highway-collapse protection
#   this pool was designed for is unchanged, only the gore/fwy_sf Tier-1
#   fallback (previously dead) is now reachable.
ep_fwy_only = gdf_ep_unique[gdf_ep_unique["ep_type"].isin(allowed_ep_types("fwy"))].copy()

# Pass (a2) — fwy_sf nodes → _TYPE_TIER gives {fwy_sf, fwy, surface, gore};
#   surface is deliberately dropped here — if no fwy-class endpoint is within
#   range the node falls through to D2 (surface pass) where surface endpoints
#   are available under D2's own (more appropriate) direction logic.
ep_fwy_sf = gdf_ep_unique[
    gdf_ep_unique["ep_type"].isin(allowed_ep_types("fwy_sf") - {"surface"})
].copy()

# Pass (b) — gore + gore_sf nodes share one pool: the union of each node
#   type's _TYPE_TIER-allowed set is {fwy, fwy_sf, gore, ramp, ramp_sf}.
#   "fwy" is further restricted to multi-route hub interchanges
#   (fw_route_count >= 2) — a deliberate heuristic beyond what _TYPE_TIER
#   encodes, kept to avoid over-matching a gore node to an isolated
#   single-route fwy endpoint that merely happens to be nearby.
_gore_allowed = allowed_ep_types("gore") | allowed_ep_types("gore_sf")
ep_gore = gdf_ep_unique[
    gdf_ep_unique["ep_type"].isin(_gore_allowed)
    & ~((gdf_ep_unique["ep_type"] == "fwy") & (gdf_ep_unique["fw_route_count"] < 2))
].copy()

# Pass (c) — ramp nodes → _TYPE_TIER gives {ramp, gore, ramp_sf}.
ep_ic_only = gdf_ep_unique[gdf_ep_unique["ep_type"].isin(allowed_ep_types("ramp"))].copy()

print(f"Pass (a)  pool — fwy, gore, fwy_sf:                 {len(ep_fwy_only):,}")
print(f"Pass (a2) pool — fwy_sf, fwy, gore:                 {len(ep_fwy_sf):,}")
print(f"Pass (b)  pool — gore, fwy(hub), ramp, fwy_sf, ramp_sf: {len(ep_gore):,}")
print(f"Pass (c)  pool — ramp, gore, ramp_sf:               {len(ep_ic_only):,}")

# ── Node masks ────────────────────────────────────────────────────────────
# gore_sf (fwy+ramp+surface): included in pass (b) alongside gore nodes;
#   _TYPE_TIER gives it access to fwy_sf/ramp_sf/fwy/ramp endpoints at Tier-1
#   (folded into ep_gore's union above).
# ramp_sf (ramp+surface): skips pass (c), routes directly to D2 surface pass.
print()
print(f"Pass (a)  nodes — fwy:     {(is_fwy_node & ~is_ramp_node & ~is_surface_node & ~is_transit_node).sum():,}")
print(f"Pass (a2) nodes — fwy_sf:  {(is_fwy_node & ~is_ramp_node &  is_surface_node & ~is_transit_node).sum():,}")
print(f"Pass (b)  nodes — gore:    {(is_fwy_node & is_ramp_node & ~is_surface_node & ~is_transit_node).sum():,}")
print(f"               gore_sf:    {(is_fwy_node & is_ramp_node &  is_surface_node & ~is_transit_node).sum():,}")
print(f"Pass (c)  nodes — ramp:    {(~is_fwy_node & is_ramp_node & ~is_surface_node & ~is_transit_node).sum():,}")
print(f"  ramp_sf → D2 surface:   {(~is_fwy_node & is_ramp_node &  is_surface_node & ~is_transit_node).sum():,}")
```

### CC Attachment Nodes

Centroid connector attachment nodes are the network-side endpoints of FT_2027 = 1
(centroid connector) links — the taps where zone centroids connect to the road
network. Zone centroids themselves (N < 3600) are excluded; only the network
attachment nodes (N ≥ 3600) are retained.

These nodes are snapped to the nearest physical centerline **vertex** (not
segment endpoint) using a simple STRtree nearest-vertex lookup — no direction
filtering, no greedy assignment. The result is written as a second layer in
`nodes_snapped.gpkg` so Stage 2 can use them as additional centerline split points.


### External Station Nodes

External station nodes (`EXTERNAL_ = 1` on the node table, N 3601–3629) are
gateway points where the model network intentionally truncates at the edge
of the modelled region — canyon passes, state lines (e.g. "I-15 to
Tremonton", "SR 190 Guardsman Pass"). Like CC attachment nodes, they are not
reliably handled by the direction-aware greedy snapper, so they get the same
simple nearest-vertex treatment and are written as a third `nodes_snapped.gpkg`
layer for Stage 2 to use as additional split points.

The same 100 m cutoff as CC nodes is kept deliberately tight: several
external nodes sit 1–13 km from any WF-county centerline (true remote
boundary points where our centerline extract simply doesn't reach), and
snapping those to whatever vertex happens to be nearest would be a
misleading match rather than a real one — better left unresolved.
